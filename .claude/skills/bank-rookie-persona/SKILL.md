# 신입행원 페르소나 분석 (은행 공통)

신입행원 교육을 설계하기 전에 **"우리 은행 신입은 누구이고, 어디서 막히고, 무엇을 실수하는가"**를 근거와 함께 정리한다. 결과물은 교육 담당자가 그대로 보고·공유할 수 있는 보고서형 HTML 한 장이다.

- 대상 기관: 시중·특수·지방·인터넷전문은행, 상호금융·저축은행 등 모든 은행
- 대상 직무: **개인금융 창구**, **기업금융**. 둘 다 고르면 직무별로 페르소나를 따로 만든다.
- 문답 상대: 은행 연수·인사 담당자, 영업점 선배·멘토. 말투는 실무 동료에게 하듯 간결하게 한다.

## 진행 순서

각 단계는 사용자 답을 받고 나서 다음으로 넘어간다. 한 번에 묻는 질문은 4개 이하로 한다.

1. **기본 정보**: `references/interview-guide.md`의 1라운드
   - 은행 이름, 기관 유형, 직무, 연수 제도(연수 기간, 배치 시점, 멘토링 유무)
   - 분석 범위(지점·지역·입행 연도)
2. **자료 모으기**: 아래 세 가지를 확인하고, 있는 것을 받는다.
   - **상품·업무 데이터**: 상품 목록, 상품설명서, 업무 매뉴얼, 민원·오류 유형 통계
     - `references/analysis-framework.md`의 직무별 체크리스트로 "신입이 실수하기 쉬운 지점"을 찾는다.
   - **설문·인터뷰 결과**: 없으면 `references/survey-kit.md`로 설문지와 인터뷰 질문지를 만들어 주고, 결과를 받으면 분석한다.
     - 받은 파일은 **분석 전에 반드시** `scripts/anonymize.py`로 가명화한다.
     - 그다음 `scripts/survey_summary.py`로 집계한다.
   - **공개 자료**: 그 은행의 채용 공고·인재상, 공시된 상품 정보, 금융당국 공개 자료(금융소비자보호법 등)
     - 웹에서 찾고, 출처 URL과 확인 날짜를 남긴다.
     - 회사 내부 자료로 추정되는 문서는 사용자가 준 경우에만 쓴다.
3. **현장 의견 문답**: `references/interview-guide.md`의 2~4라운드
   - 담당자·선배의 경험을 묻는다. 답은 출처 유형 `현장의견`으로 기록한다.
   - 자료와 현장 의견이 어긋나면 숨기지 말고 **불일치**로 표시하고 사용자에게 확인한다.
4. **분석과 페르소나 작성**: `references/persona-schema.md` 형식의 `persona.json`을 쓴다.
   - 대표 페르소나 1명(직무별)
   - 성장 5단계: 기본은 입행 1주 / 1개월 / 3개월 / 6개월 / 1년. 그 은행의 연수·배치 일정에 맞춰 이름과 시점을 바꾼다.
   - 어려움 맵, 핵심 발견, 교육 제안
5. **보고서 만들기**
   ```bash
   python scripts/render_report.py persona.json --out <은행>_신입행원_페르소나.html
   ```
   - 스크립트가 신뢰도를 출처로 다시 계산한다. `경고:`가 나오면 고친 뒤 다시 만든다.
   - 렌더된 화면을 열어 보고 겹침·잘림이 없는지 확인한다.
6. **검토 문답**
   - 보고서를 보여 주고 "틀린 것, 빠진 것, 현장 감각과 다른 것"을 묻는다.
   - 답을 반영해 `persona.json`을 고치고 다시 렌더한다. 사용자가 됐다고 할 때까지 반복한다.

## 근거와 신뢰도 규칙

모든 항목(특성·어려움·발견·제안)은 출처 ID를 하나 이상 단다. 출처 유형은 4가지다.

| 유형 | 예 |
|---|---|
| `데이터` | 상품 목록, 매뉴얼, 민원 통계 |
| `설문` | 응답자 수 n을 함께 기록 |
| `공개자료` | URL과 확인 날짜를 함께 기록 |
| `현장의견` | 누가(직책 수준만) 말했는지 기록 |

신뢰도는 스크립트가 출처로 자동 계산한다. 사람이 올려 적을 수는 없고, 낮출 수만 있다.

| 등급 | 조건 |
|---|---|
| **높음** | 서로 다른 유형의 출처 2개 이상이 같은 내용을 가리킴 |
| **보통** | 데이터·설문·공개자료 중 1개 유형만 있음 |
| **추정** | 현장의견만 있거나, 설문 응답자가 5명 미만임 |

- 근거 없는 항목은 쓰지 않는다. 꼭 필요하면 "가설"로 적고 추정 등급을 준다.
- 숫자(비율·건수·응답 분포)는 받은 자료나 집계 결과에서만 가져온다.

## 개인정보 규칙

- 설문·인터뷰 원자료는 `scripts/anonymize.py`로 가명화한 파일만 분석한다.
  - 지우는 것: 이름·사번·연락처·이메일 열과 문장 속 전화번호·이메일·사번·직급 호칭
  - 바꾸는 것: 지점명은 `지점A`처럼 바꾼다.
- 가명화 결과 요약(지운 열, 바꾼 개수)을 사용자에게 보여 주고, 남은 식별 정보가 없는지 확인을 받는다.
- 보고서에는 집계만 넣는다.
  - 응답자 5명 미만인 문항은 분포를 숨긴다.
  - 자유응답 인용은 전체 응답자 5명 이상일 때만, 식별될 만한 내용을 뺀 짧은 문장으로 넣는다.
- 원자료와 가명화 전 파일은 보고서 폴더에 복사하지 않는다. 저장소에 올리지 않도록 안내한다.

## 하지 않는 것

- 특정 은행의 내부 인사 평가나 개인 역량 평가. 이 스킬은 **집단 페르소나**만 만든다.
- 공식 자료인 것처럼 꾸미기. 보고서에는 "교육 설계 참고용 분석"이라는 문구와 작성자·날짜가 들어간다.
- 실제 상품 정보를 기억에 의존해 쓰기. 상품 숫자는 받은 데이터나 공식 공시에서만 가져온다.
