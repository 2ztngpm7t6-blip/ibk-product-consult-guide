# 가이드 업데이트

상품 정보가 바뀌었을 때 `data/products.json`을 고치고 `IBK_상품상담가이드.html`을 다시 만든다.

## 절차

1. **무엇이 바뀌었는지 확인한다.** 상품 ID, 바뀐 항목(금리·우대조건·한도·혜택·상품설명서 번호), 근거를 묻는다.
2. **공식 페이지를 다시 확인한다.**
   - 해당 상품의 `source_url`(IBK기업은행 공식 홈페이지)을 브라우저로 열어 바뀐 값을 직접 확인한다.
   - 사용자가 말한 값과 공식 페이지 값이 다르면, 고치기 전에 사용자에게 알린다.
   - 공식 페이지로 확인할 수 없는 값은 넣지 않는다.
3. **`data/products.json`을 고친다.**
   - 바뀐 필드만 고친다.
   - 전체 확인 기준일 `checked_at`은 25개를 모두 다시 확인했을 때만 바꾼다.
   - 일부만 확인했으면 `source_note`에 "DEP-01은 YYYY-MM-DD 재확인"처럼 덧붙인다.
4. **규칙을 맞춘다.**
   - `report-studio/template.html`의 `R` 규칙에도 숫자가 있다. 금리(`terms`, `max`), 한도(`monthly`, `lump`), 카드 실적(`minSpend`, `tiers`)이 그 예다.
   - JSON과 같은 값으로 고친다.
5. **다시 빌드한다.**
   ```bash
   sh report-studio/build.sh
   ```
6. **확인한다.** 브라우저에서 해당 상품의 3개 탭(직원 교육용·고객 안내용·창구 영업용)이 오류 없이 나오는지, 바뀐 숫자가 보이는지 본다.
7. **새 상품을 추가할 때**
   - ID 규칙(DEP-/CRD-/INS- + 번호)을 따른다.
   - JSON 항목과 `R` 규칙을 함께 만든다.
   - 교육자료 기준(`references/personas.md`)의 상품 범위에도 넣을지 사용자에게 묻는다.
8. **보고한다.** 바뀐 내용(전 → 후), 확인한 공식 페이지, 빌드 결과를 알린다. 커밋·푸시는 사용자가 요청할 때만 한다.

## 정기 점검 거리

- 상품설명서 유효기간(`doc`의 기간)이 지난 상품. 예: 주택청약종합저축 설명서는 2026-11-10에 만료
- 판매 중지된 상품(공식 페이지에서 사라졌거나 신규 판매 중지 표시)
